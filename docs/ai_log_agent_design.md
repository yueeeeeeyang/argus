# Argus 通用智能体设计（v3，当前实现）

本文档描述 Argus 智能分析的现行架构：日志加载时物化到工作目录，AI 层是在该目录上
运行的通用智能体（bash + 文件读取工具），产品功能由 Skill 知识注入提供，不再包含
任何硬编码的诊断流程、结构化报告或专用分析工具。

## 一、设计动机

早期版本为 AI 配备了 16 个 source_ref 结构化工具、固定十二阶段分析流程、隔离复核和
结构化诊断报告。实践发现该方案存在根本矛盾：

1. 专用工具把"如何分析日志"硬编码进产品，模型无法组合出设计者预料之外的调查路径；
2. 归档读取链路复杂（虚拟路径、密码快照、流式/落盘双后端），浏览器、搜索与 AI 各自
   重复解压；
3. 结构化报告与证据校验带来大量一次性代码，维护成本远超其产出价值。

v3 方案的用户决策（已确认）：

- **工作目录物化**：加载时把普通来源复制、压缩包解压进临时工作目录；左侧目录树直接
  显示工作目录真实结构；浏览器与 AI 全部只读普通文件。
- **通用智能体**：不硬编码任何诊断逻辑；内置 bash + 文件读取工具，只允许在工作目录
  内执行；白名单外命令弹窗确认。智能分析与 Agent 助手都是其上的薄壳，不保留旧行为。
- **Skill 体系**：方法论以用户导入的知识文本注入，与代码解耦；不提供内置 Skill。

## 二、总体架构

```
加载流程：选择来源 → 物化阶段【loader/workspace.rs】
  ├─ 普通文件/目录 → 复制进 cache/workdirs/<id>/<来源根标签>/
  ├─ 压缩包（含嵌套）→ 解压进同结构目录
  └─ 密码包 → 占位节点，解锁后向当前工作目录追加物化
  → 对工作目录做一次普通目录扫描建树（loader/source_scanner.rs）
  → 左侧目录树 = 工作目录结构（Directory/LogFile/占位/Unsupported）

读取层：LogFileReader 只面对普通文件（小文件 mmap InMemory / 大文件 Paged）

AI 层：src/agent/agent_loop.rs 通用单轮模型循环
  ├─ preamble = 安全骨架 + <CONFIGURED_SYSTEM_PROMPT> + <SKILLS>
  └─ 工具 = list_loaded_sources + read_file + bash（均限定工作目录）
两条薄壳：agent_window（智能分析独立窗口）/ assistant_panel（主窗口助手）
Skill：src/agent/skills.rs 仅用户导入（目录/ZIP），config_root/ai/skills/ 落盘
```

两条产品线的差异只剩：入口与历史（助手有跨模型中立历史）；Skill 集两条线共用。

## 三、工作目录物化

物化器（`loader/workspace.rs`）在日志加载时把全部来源转换为普通文件：

- 选址 `argus_config_dir()/cache/workdirs/<uuid>/`；顶层布局 `<标签>/`，标签清洗为合法
  目录名，同名根追加 ` (1)` 消歧。
- 单批解压总字节上限（`LoaderConfig.workspace_extract_budget_bytes`，默认 8 GiB）、
  单条目 4 GiB 上限；zip slip 清洗（拒 `..`/绝对路径/控制字符/Windows 保留名）；重名
  冲突条目拒绝；超限根回滚降级为警告节点，不阻断其它来源。
- 密码包两阶段：加载时保持"需要密码"占位；解锁后向当前工作目录追加物化并重扫顶层。
- 生命周期：替换加载时后台删除旧工作目录（Windows 句柄重试）；窗口关闭钩子删除；
  启动时清扫 `cache/workdirs` 与历史 `log_pages` 残留。

## 四、通用智能体

### 4.1 统一循环（`agent/agent_loop.rs`）

`AgentLoopRequest` 携带问题、中立历史、配置快照、工作区清单、凭据与实时通道；
`AgentLoopNote` 区分两条产品线（只影响开场状态事件与完成事件形态）。循环职责：

- reqwest/DeepSeek/OpenAI 兼容客户端构建；官方 DeepSeek 端点附加 thinking 参数；
- 无限次指数退避重试（1s 起步、30s 封顶；仅传输类故障可重试，配置类错误立即失败）；
  重试前发布 `AssistantAttemptReset`，界面丢弃未完成的流式正文；
- Rig 多轮流式消费（思考/正文增量、权威 usage）、预算计数、工具轨迹；
- 模型请求边界串行消费追加提示（`USER_HINT` 边界文档），重试只在首次请求重放已消费
  消息；会话退出守卫关闭消息门闩、拒绝残留提示、收敛未决 bash 审批并停止审批答复泵。

### 4.2 工作区清单（`agent/session.rs`）

会话启动时从注册表 + 工作目录直接固化 `SourceScopeSnapshot`（不触发文件系统扫描；
来源树在加载时已一次性完整初始化）：每个日志文件携带工作目录相对路径（正斜杠）、
真实绝对路径、命中日志类型的名称与说明全文、已知大小；另携带工作目录根、兜底解码
编码与原文授权开关。模型引用的路径与工具实际解析的路径保持同一坐标系。

### 4.3 工具（`agent/tools.rs`，全部限定工作目录）

1. **`list_loaded_sources { path_prefix?, limit }`**：工作区清单分页；返回相对路径、
   绝对路径、大小与命中的日志类型说明。
2. **`read_file { path, offset_line?, max_lines? }`**：词法规范化先拒绝 `..` 越界，
   再 canonicalize 拦截符号链接逃逸；≤64 KiB / ≤2000 行窗口读取，按检测编码解码，
   返回续读偏移；`allow_raw_log_content=false` 时只返回元数据；输出经敏感信息遮蔽。
3. **`bash { command, timeout_ms? }`**：cwd=工作目录，`kill_on_drop`；默认 60s、上限
   300s；stdout/stderr 各自截断（96/32 KiB）并遮蔽；非零退出码如实返回。
   - **白名单自动执行**（只读命令）：`ls cat grep head tail wc find sort uniq awk sed
     cut tr echo pwd stat file du df`——按段（管道/`;`/`&&`/换行）解析 argv[0]，跳过
     段首环境变量赋值；sed `-i`、find `-delete/-exec` 族、sort `-o`、awk `system()`、
     重定向 `>`、命令替换 `$(`/反引号、`~` 与任何越出工作目录的路径形态参数，一律转
     用户确认。
   - **确认通道**：工具挂起等待 oneshot；`AgentEvent::BashApprovalRequired` 携带完整
     命令，两个界面渲染内联确认卡片（批准/拒绝）；60s 未答复、会话取消或界面关闭都
     按拒绝收敛，并发布 `BashApprovalOutcome` 固化卡片状态。
   - **授权语义如实告知**：`allow_raw_log_content=false` 无法过滤 bash 输出，在安全
     骨架中降级为指令级约束。

### 4.4 安全骨架（preamble）

英文书写、位于系统提示词最高层，不可被用户提示词、日志内容或工具输出覆盖：不可信
数据边界、工作目录沙箱、证据纪律（不得虚构读取事实）、注入防御、输出脱敏、只读与
非攻击性约束、原文授权状态与 @ 选择来源的说明；要求以中文 Markdown 回答。

## 五、Skill 系统（`agent/skills.rs`）

- 格式：`<skill-dir>/SKILL.md`，`---` frontmatter（`name`/`description`，手写极简解析）
  + Markdown 正文 ≤32 KiB；名称限 `[A-Za-z0-9._-]` 且 ≤64 字节。
- 不提供内置 Skill；方法论与领域知识全部由用户导入，未导入时不注入 `<SKILLS>` 区块。
- 注入：安全骨架 → `<CONFIGURED_SYSTEM_PROMPT>` → `<SKILLS>`（按名称排序，
  `<SKILL name>` 边界）；区块总量 ≤24 KiB，截断以用户可见轨迹记录 WARN。
- 导入（设置页"Skill 管理"）：系统路径对话框选目录或 `.zip`；目录递归收集（拒符号
  链接），zip 条目 zip slip 清洗并定位唯一含 SKILL.md 的顶层目录；统一预算 ≤64 文件、
  ≤2 MiB；解析失败或与既有导入同名冲突拒绝且不留残留；产物复制到
  `config_root/ai/skills/<name>/`。
- 持久化：`AiConfig.disabled_skills`（默认空=全启用），保存后下一轮会话生效。

## 六、界面与交互

- **智能分析独立窗口**（`ui/agent_window.rs`）：消息瀑布流（问题/轨迹/工具组/思考/
  正文/bash 审批卡片按时间交错）；顶部用量栏；底部追加提示（门闩线性化，会话结束
  拒绝残留）；发起新分析时旧窗口已终态则关闭重建，运行中拒绝并发。
- **交互助手面板**（`ui/assistant_panel.rs`）：同一循环的薄壳；跨模型中立历史按
  上下文窗口一半预算裁剪最早完整轮次；`@` 候选与注入元数据使用工作目录路径前缀，
  界面不展示 Argus 生成的元数据。
- **bash 审批卡片**（`ui/components/bash_approval.rs`，两处共用）：完整命令、白名单
  外原因提示、批准/拒绝按钮与结论固化。

## 七、测试方案

每阶段 `cargo fmt && cargo clippy --all-targets && cargo test` 全绿（当前 494 项）。
重点覆盖：

- 物化器：复制/解压/zip slip/重名冲突/预算回滚/嵌套/GZIP 命名/密码包追加（loader 模块）；
- 清单：树 → workspace 路径映射、多根消歧、日志类型说明全文固化；
- read_file：`..`/绝对路径/符号链接越界拒绝、行窗口与续读偏移、未授权只回元数据；
- bash：白名单与管道逐段判定、重定向/命令替换/破坏性参数/越界路径转确认、审批超时
  拒绝、退出码与输出截断；
- Skill：frontmatter 解析与拒绝条件、默认集筛选、禁用过滤、目录/ZIP 导入、同名冲突、
  注入边界与预算截断；
- 手动冒烟：大包加载与浏览、密码包解锁、两条 AI 产品线问答与 bash 审批弹窗、Skill
  全流程、Windows 删除重试。

## 八、与旧设计（v2）的差异

| 旧机制 | 现状 |
|---|---|
| 16 个 source_ref 结构化工具及引擎 | 删除；由 3 个领域无关工作区工具取代 |
| source_ref 不透明引用与安全层 | 删除；清单直接携带工作目录真实路径 |
| 固定十二阶段 + 隔离复核 | 删除；方法论由用户导入的 Skill 知识文本承载 |
| 结构化诊断报告与落盘 | 删除；模型以 Markdown 直接回答 |
| 引用卡片 / 证据复读 / `open_ai_evidence` | 删除 |
| 归档虚拟路径与流式/落盘双后端 | 删除；加载期一次性物化为普通文件 |
| 每会话重扫描来源树 | 删除；加载时一次性完整初始化，快照直接构建 |

## 九、风险与限制

- **bash 沙箱是尽力约束**：cwd + 白名单路径校验 + 确认卡片展示完整命令；不做 OS 级
  沙箱。工作目录是可丢弃的副本，批准写操作的最坏后果是重新加载来源。
- **普通来源复制的 I/O 成本**：大文件加载时一次性复制（进度明示），换取读取/AI/搜索
  全链路统一；同设备硬链接优化为后续可选项。
- **Skill 知识质量**：效果依赖模型对导入知识文本的遵循；Skill 只影响提示词，
  不获得额外执行能力，未导入时模型仅依靠安全骨架与通用工具能力工作。
- **日志浏览器、本地 analysis 页签、日志搜索不受 AI 改动影响**；物化只让其读取更快。
